# CleanOps Nexus Acceptance Criteria (Wave 01)

## 1. Architecture

- System architecture document exists and is internally consistent.
- Domain boundaries and tenant isolation rules are explicit.
- API v1 contract draft covers all MVP modules.

## 2. Engineering Foundations

- Backend/mobile/web foundation plans are documented.
- Branch naming and PR policy are defined and followed.
- Helper-agent roles and responsibilities are documented.

## 3. Quality

- QA strategy defines unit/integration/e2e approach.
- Security checks and RBAC coverage are defined.
- CI gate expectations are documented.

## 4. Governance

- Main agent owns integration and final review.
- Each delivery stream has objective, output, and done condition.
- Risks and next actions are listed in project reports.

## 5. Done for Kickoff

- Kickoff docs committed on branch feat/cleanops-nexus-kickoff.
- Project packet includes brief, architecture, API contract, QA strategy, and acceptance criteria.
- Ready to open PR when repository write auth is available.
